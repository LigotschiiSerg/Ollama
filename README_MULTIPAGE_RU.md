# PDF Desk: одна таблица на нескольких страницах

## Изменение архитектуры

- `Page` и `Table` хранят исходные фрагменты (позиция в документе и отдельные ячейки); информация о происхождении не теряется.
- `Table.continues_from` связывает очередной фрагмент с предыдущим фрагментом той же логической таблицы.
- В Django открывается целая логическая таблица со всеми строками и номерами исходных страниц.
- В SQLite создаётся **одна физическая таблица на логическую таблицу**; дополнительное поле `_source_page` показывает происхождение строки.
- Одинаковая шапка следующей страницы автоматически исключается из повторных строк. Если шапки нет, первая строка продолжения остаётся данными.
- Старые PDF повторно распознавать не нужно для объединения уже полученных фрагментов.

## Установка

Сделайте копию `db.sqlite3` и `media`, остановив обработчик и Django.

```
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py test documents.tests.test_continuation
```

После переноса старой базы:

```
python manage.py export_pdf_tables
```

Команда безопасно перестраивает экспортные SQLite-таблицы и пытается связать продолжения, если уверена в совпадении шапок или названия.

## Ручное соединение неоднозначных продолжений

Определите ID документа:

```
python manage.py shell -c "from documents.models import Document; print(list(Document.objects.values('id','title')))"
```

Просмотрите ID фрагментов:

```
python manage.py list_pdf_tables --document 1
```

Если таблица ID 10 заканчивается на странице 11, а ID 11 продолжает её на странице 12:

```
python manage.py merge_pdf_tables 10 11
```

Для третьей страницы продолжения выполните `python manage.py merge_pdf_tables 11 12`.

**Не объединяйте две разные таблицы только потому, что они стоят на соседних страницах.** Команда проверяет одинаковое число конечных столбцов; смысловое соответствие пользователь подтверждает сам. Существующие ячейки не изменяются.

## Ограничения

- Автоматическое объединение намеренно консервативное: когда заголовок отсутствует, требуется ручное подтверждение.
- Неправильно распознанную Docling геометрию/число столбцов объединение не исправит.
- Структура rowspan/colspan каждого исходного фрагмента сохранена; на стыке страниц один rowspan не может визуально пересекать два HTML-фрагмента.
- Для очень больших документов экспорт пересоздаёт таблицу целиком после обработки, поэтому время экспорта растёт с объёмом.
- Полный OCR и тесты Django необходимо провести в вашем окружении с установленными зависимостями.
